(FitLog Project Documentation & Presentation Book)

ບົດທີ 1: ບົດນຳ (Chapter 1: Introduction)

1.1 ຄວາມເປັນມາ ແລະ ຄວາມສຳຄັນ (Background & Significance)

ໃນຍຸກປັດຈຸບັນ, ການຮັກສາສຸຂະພາບ ແລະ ການອອກກຳລັງກາຍ (Fitness & Well-being) ໄດ້ກາຍມາເປັນສ່ວນໜຶ່ງທີ່ສຳຄັນໃນຊີວິດປະຈຳວັນຂອງຄົນເຮົາ. ເຖິງຢ່າງໃດກໍຕາມ, ບັນຫາທີ່ຫຼາຍຄົນພົບພໍ້ແມ່ນ ການຂາດຄວາມຕໍ່ເນື່ອງ (Consistency) ແລະ ການບໍ່ມີການຕິດຕາມຂໍ້ມູນທີ່ມີປະສິດທິພາບ. ຜູ້ໃຊ້ຫຼາຍຄົນອອກກຳລັງກາຍໂດຍບໍ່ຮູ້ວ່າຕົນເອງເຜົາຜານແຄລໍຣີໄປເທົ່າໃດ, ອອກກຳລັງກາຍປະເພດໃດຫຼາຍທີ່ສຸດ, ຫຼື ຄວນບໍລິໂພກອາຫານເທົ່າໃດຈຶ່ງຈະເໝາະສົມກັບເປົ້າໝາຍຮ່າງກາຍ (Weight Loss, Muscle Gain, or Maintenance).

ເພື່ອແກ້ໄຂບັນຫາດັ່ງກ່າວ, ໂຄງການພັດທະນາ FitLog ຈຶ່ງຖືກສ້າງຂຶ້ນ. FitLog ແມ່ນ Mobile Application ທີ່ອອກແບບມາເພື່ອເປັນຕົວຊ່ວຍສ່ວນຕົວໃນການບັນທຶກ ແລະ ຕິດຕາມການອອກກຳລັງກາຍ ພ້ອມທັງຄຳນວນໂພຊະນາການທີ່ເໝາະສົມກັບຮ່າງກາຍແບບອັດຕະໂນມັດ ໂດຍເນັ້ນໃສ່ປະສົບການຜູ້ໃຊ້ (UX/UI) ທີ່ສວຍງາມ, ທັນສະໄໝ, ເຮັດວຽກໄດ້ວ່ອງໄວ, ແລະ ປົກປ້ອງຄວາມເປັນສ່ວນຕົວຂອງຂໍ້ມູນຜູ້ໃຊ້ (Data Privacy) ດ້ວຍການເກັບຂໍ້ມູນທັງໝົດໄວ້ໃນອຸປະກອນຂອງຜູ້ໃຊ້ເອງ (Offline-First local database).

1.2 ຈຸດປະສົງຂອງໂຄງການ (Project Objectives)

  1. ເພື່ອພັດທະນາລະບົບບັນທຶກການອອກກຳລັງກາຍ ທີ່ມີຄວາມຍືດຫຍຸ່ນ ສາມາດບັນທຶກຂໍ້ມູນປະເພດການອອກກຳລັງກາຍ, ໄລຍະເວລາ, ແຄລໍຣີ ແລະ ວັນທີໄດ້ຢ່າງຊັດເຈນ.
  2. ເພື່ອສ້າງລະບົບຕິດຕາມຄວາມຕໍ່ເນື່ອງ (Gamification) ຜ່ານ Streak counter ເພື່ອກະຕຸ້ນ ແລະ ສ້າງແຮງຈູງໃຈໃຫ້ຜູ້ໃຊອກກຳລັງກາຍຢ່າງສະໝໍ່າສະເໝີ.
  3. ເພື່ອອອກແບບ ແລະ ສ້າງລະບົບວິເຄາະສະຖິຕິ (Data Visualization) ທີ່ເຂົ້າໃຈງ່າຍ ຜ່ານກຣາຟຫຼາກຫຼາຍຮູບແບບ (Bar Chart, Line Chart, Pie Chart) ເຮັດໃຫ້ຜູ້ໃຊ້ເຫັນແນວໂນ້ມ ແລະ ພຶດຕິກຳການອອກກຳລັງກາຍຂອງຕົນເອງ.
  4. ເພື່ອຄຳນວນໂພຊະນາການ ແລະ ພະລັງງານສ່ວນບຸກຄົນ ໂດຍອີງໃສ່ຂໍ້ມູນທາງກາຍະພາບຂອງຜູ້ໃຊ້ (Weight, Height, Age, Activity level, Goal) ເພື່ອແນະນຳປະລິມານ Macronutrients (Protein, Carbs, Fat) ທີ່ເໝາະສົມ.

1.3 ຂອບເຂດຂອງໂຄງການ (Project Scope)

  • ຂໍ້ມູນທ້ອງຖິ່ນ (Local-First Database): ລະບົບເກັບຂໍ້ມູນທັງໝົດໃນເຄື່ອງຜູ້ໃຊ້ ໂດຍບໍ່ຕ້ອງໃຊ້ Internet ເພື່ອຄວາມປອດໄພຂອງຂໍ້ມູນ ແລະ ຄວາມວ່ອງໄວ.
  • Prefix CRUD: ສາມາດ ເພີ່ມ, ລຶບ, ແກ້ໄຂ, ຄົ້ນຫາ ແລະ ກັ່ນຕອງ (Filter) ຂໍ້ມູນການອອກກຳລັງກາຍໄດ້ທັງໝົດ.
  • ລະບົບຈັບເວລາ (Built-in Stopwatch): ມີລະບົບຈັບເວລາອອກກຳລັງກາຍ ແລະ ສາມາດສົ່ງຄ່າໄລຍະເວລາໄປຍັງຟອມບັນທຶກໄດ້ທັນທີ.
  • ການຄຳນວນພະລັງງານ ແລະ BMI (Body Metrics & BMR/TDEE): ຄຳນວນຄ່າ BMI, BMR, TDEE ແລະ Macronutrients ອັດຕະໂນມັດຫຼັງຈາກຜູ້ໃຊ້ຕັ້ງຄ່າ Profile.
  • ການສະແດງຜົນສະຖິຕິ (Interactive Charts): ສະແດງກຣາຟແຄລໍຣີລາຍວັນ, ກຣາຟສັດສ່ວນປະເພດການອອກກຳລັງກາຍ ແລະ ທ່າອ່ຽງໄລຍະເວລາ.
  • ຮອງຮັບສອງ Theme (Dark & Light Theme): ສາມາດສະລັບໂໝດມືດ ແລະ ໂໝດສະຫວ່າງໄດ້ຕາມຄວາມຕ້ອງການ.

1.4 ຜົນປະໂຫຍດທີ່ຄາດວ່າຈະໄດ້ຮັບ (Expected Benefits)

  • ສຳລັບຜູ້ໃຊ້: ໄດ້ຮັບເຄື່ອງມືທີ່ຊ່ວຍໃຫ້ສາມາດຕິດຕາມສຸຂະພາບ ແລະ ການອອກກຳລັງກາຍໄດ້ຢ່າງເປັນລະບົບ, ມີແຮງຈູງໃຈໃນການອອກກຳລັງກາຍຫຼາຍຂຶ້ນຈາກ Streak, ແລະ ສາມາດວາງແຜນການກິນອາຫານໃຫ້ຖືກຕ້ອງຕາມເປົ້າໝາຍສຸຂະພາບ.
  • ສຳລັບນັກພັດທະນາ: ໄດ້ຮຽນຮູ້ ແລະ ປະຕິບັດການພັດທະນາແອັບພລິເຄຊັນດ້ວຍ Flutter ໂດຍໃຊ້ສະຖາປັດຕະຍະກຳ BLoC, ການຈັດການຖານຂໍ້ມູນ Isar Database ເຊິ່ງເປັນ NoSQL ທີ່ໄວທີ່ສຸດໃນປັດຈຸບັນ ແລະ ການສ້າງ UI ລະດັບ Premium.

ບົດທີ 2: ການອອກແບບ ແລະ ສະຖາປັດຕະຍະກຳລະບົບ (Chapter 2: System Design & Architecture)

2.1 ສະຖາປັດຕະຍະກຳຂອງແອັບພລິເຄຊັນ (App Architecture)

FitLog ນຳໃຊ້ສະຖາປັດຕະຍະກຳການອອກແບບແບບ Layered Architecture ຮ່ວມກັບ BLoC Pattern ເພື່ອແຍກສ່ວນຂອງ User Interface (UI), Business Logic, ແລະ Data Access ອອກຈາກກັນຢ່າງເດັດຂາດ (Separation of Concerns).

2.2 ເທັກໂນໂລຊີທີ່ເລືອກໃຊ້ (Technology Stack)

ເທັກໂນໂລຊີ (Tech Stack) ລາຍລະອຽດການນຳໃຊ້ ເຫດຜົນ ແລະ ຈຸດເດັ່ນ
Flutter (Dart) Framework ຫຼັກໃນການພັດທະນາ ຂຽນ Code ດຽວລັນໄດ້ທັງ iOS, Android, Web, and Desktop, ໃຫ້ UI ທີ່ລື່ນໄຫຼ.
Isar Database ຖານຂໍ້ມູນ Local NoSQL ຄວາມໄວສູງ ເກັບຂໍ້ມູນແບບ Offline, ວ່ອງໄວກວ່າ SQLite ຫຼາຍເທົ່າ, ຮອງຮັບ Streams.
flutter_bloc ການຈັດການ State Management ແຍກ Logic ອອກຈາກ UI ເຮັດໃຫ້ Code ເປັນລະບົບ ແລະ ທົດສອບງ່າຍ.
go_router ການຈັດການ Navigation & Routing ຮອງຮັບ ShellRoute ສ້າງ Bottom Navigation ທີ່ສະດວກ ແລະ ລື່ນໄຫຼ.
fl_chart ລະບົບສະແດງຜົນກຣາຟວິເຄາະ ສ້າງກຣາຟທີ່ສວຍງາມ, ມີ Animation ແລະ ຮອງຮັບການ Touch/Interaction.

2.3 ການອອກແບບຖານຂໍ້ມູນ (Data Model & Schema)

1. Workout Schema (ເກັບຂໍ້ມູນການອອກກຳລັງກາຍ)

  • id: Id (Auto-increment, Primary Key)
  • name: String (ຊື່ກິດຈະກຳ ເຊັ່ນ "Morning Cardio")
  • duration: int (ໄລຍະເວລາ ເປັນນາທີ)
  • calories: int (ແຄລໍຣີທີ່ເຜົາຜານ)
  • date: DateTime (ວັນທີ ແລະ ເວລາ, ຕັ້ງ @Index ເພື່ອ query ໄວ)
  • notes: String? (ບັນທຶກເພີ່ມເຕີມ - optional)
  • type: String (ປະເພດກິດຈະກຳ ເຊັ່ນ Running, Swimming, Yoga - ຕັ້ງ @Index)
💡 ຂໍ້ຄວນລະວັງ: ການໃສ່ @Index() ໃຫ້ກັບ date ແລະ type ແມ່ນມີຄວາມສຳຄັນຫຼາຍ ເພາະຈະຊ່ວຍໃຫ້ລະບົບຄົ້ນຫາ ແລະ ກັ່ນຕອງຂໍ້ມູນປະຫວັດ (Filter) ເຮັດວຽກໄດ້ວ່ອງໄວເຖິງແມ່ນວ່າຈະມີຂໍ້ມູນຫຼາຍພັນແຖວກໍຕາມ.

2. UserProfile Schema (ເກັບຂໍ້ມູນຮ່າງກາຍ ແລະ ເປົ້າໝາຍ)

ເກັບຂໍ້ມູນກາຍະພາບເພື່ອຄຳນວນໂພຊະນາການ ແລະ ສຸຂະພາບ: gender, weight, height, age, activityLevel, goal.

ສູດຄຳນວນອັດຕະໂນມັດ (Computed Properties):

  • BMI: Weight (kg) / (Height (m))²
  • BMR (Mifflin-St Jeor):
    • ເພດຊາຍ: 10 × weight + 6.25 × height - 5 × age + 5
    • ເພດຍິງ: 10 × weight + 6.25 × height - 5 × age - 161
  • TDEE: BMR × Activity Factor (1.2 to 1.9)
  • Adjusted Calories (ເປົ້າໝາຍ): ຫຼຸດນ້ຳໜັກ = TDEE - 500 kcal | ເພີ່ມກ້າມ = TDEE + 300 kcal
  • Macros: Protein (30%), Carbs (40%), Fat (30% ຂອງພະລັງງານທັງໝົດ)

2.4 ລະບົບການອອກແບບ UI/UX ແລະ ລະບົບສີ (Design System & App Theme)

  • Typography: ໃຊ້ຟອນທ໌ HinsiewLAO (Hinsiew-SemiBold.otf) ເປັນຫຼັກ ເຮັດໃຫ້ພາສາລາວສະແດງຜົນໄດ້ມີມິຕິ ແລະ ອ່ານງ່າຍ.
  • Color System (AppColors): ໃຊ້ສີ Teal (#009688) ເປັນສີຫຼັກ ໃຫ້ຄວາມຮູ້ສຶກເຖິງພະລັງງານ ແລະ ສຸຂະພາບ ຕັດດ້ວຍສີ Coral Orange (#FF7043) ເພື່ອດຶງດູດສາຍຕາ.
  • Card Design: ໃຊ້ Gradient gradients ທີ່ແຕກຕ່າງກັນໃນການສະແດງຜົນ Dashboard (Teal ສໍາລັບ Workout, Orange ສໍາລັບ Calories, Indigo ສໍາລັບ Duration) ເພື່ອບໍ່ໃຫ້ຜູ້ໃຊ້ອ່ານຂໍ້ມູນສັບສົນ.

3.2 ການວິເຄາະໜ້າຈໍ ແລະ ຟັງຊັນຫຼັກ (Detailed Screen & Feature Breakdown)

❶ ໜ້າຫຼັກ (Home Screen)

ເປັນ Dashboard ສູນກາງສະແດງຜົນສຸຂະພາບລາຍວັນ ປະກອບດ້ວຍ Streak Card 🔥 ເພື່ອສະແດງມື້ທີ່ອອກກຳລັງກາຍຕິດຕໍ່ກັນ, Nutrition Card 🥗 ສະແດງແຄລໍຣີເປົ້າໝາຍ ແລະ Macronutrients progress bars ທີ່ຄຳນວນມາໃຫ້ແລ້ວ, General Stats ສະຫຼຸບຜົນງານທັງໝົດ, ແລະ Recent Workouts 3 ລາຍການຫຼ້າສຸດ.

❷ ໜ້າປະຫວັດ (History Screen)

ສູນລວມຈັດການ ແລະ ກວດສອບຂໍ້ມູນການອອກກຳລັງກາຍໃນອະດີດ ມີ Search Bar 🔍 ພ້ອມ Filter Chips 🏷️ ຕາມປະເພດກິດຈະກຳ. ຜູ້ໃຊ້ສາມາດກົດເບິ່ງລາຍລະອຽດ, ກົດຄ້າງເພື່ອແກ້ໄຂ ຫຼື ປັດ (Swipe to delete) ເພື່ອລຶບຂໍ້ມູນໄດ້ທັນທີ.

❸ ໜ້າສະຖິຕິ (Statistics Screen)

ວິເຄາະຂໍ້ມູນອອກມາເປັນພາບກຣາຟ (Data Visualization) ໂດຍໃຊ້ FL Chart ປະກອບດ້ວຍ 3 ກຣາຟຫຼັກ: ກຣາຟແທ່ງແຄລໍຣີລາຍວັນ (Bar Chart), ກຣາຟວົງມົນສັດສ່ວນປະເພດ workout (Pie Chart), ແລະ ກຣາຟເສັ້ນແນວໂນ້ມໄລຍະເວລາ (Line Chart).

❹ ໜ້າຈັບເວລາ (Timer Screen)

ເຄື່ອງມືຈັບເວລາອອກກຳລັງກາຍແບບ Real-time ທີ່ອອກແບບດ້ວຍ CustomPaint ວາດ Gradient Arc ທີ່ສວຍງາມ ເມື່ອອອກກຳລັງກາຍສຳເລັດ ສາມາດກົດ Save ເພື່ອສົ່ງຄ່າເວລາໄປໜ້າ Add ໄດ້ທັນທີ.

💡 ຄຳແນະນຳ: ໃຫ້ແນ່ໃຈວ່າທ່ານໄດ້ຕິດຕັ້ງ Flutter SDK ລຸ້ນ >= 3.10.1 ຮຽບຮ້ອຍແລ້ວ ກ່ອນຈະເລີ່ມລັນຄຳສັ່ງລຸ່ມນີ້.

flutter run

flutter run -d chrome

ໂຄງການພັດທະນາແອັບພລິເຄຊັນ FitLog ປະສົບຜົນສຳເລັດໃນການສ້າງເຄື່ອງມືຕິດຕາມການອອກກຳລັງກາຍ ແລະ ໂພຊະນາການທ້ອງຖິ່ນ (Local-First Offline) ທີ່ເຮັດວຽກໄດ້ຢ່າງວ່ອງໄວ ແລະ ມີຄວາມຫຼູຫຼາສວຍງາມ.

ແຜນພັດທະນາໃນອະນາຄົດ (Future Roadmap):

  1. Cloud Sync & Backup: ເພີ່ມການ Backup ຂໍ້ມູນຂຶ້ນ Cloud (Supabase/Firebase) ປ້ອງກັນຂໍ້ມູນສູນຫາຍ.
  2. Wearable Integration: ເຊື່ອມຕໍ່ກັບ Smartwatches ເຊັ່ນ Apple Watch, Garmin ເພື່ອດຶງຂໍ້ມູນ Heart Rate.
  3. AI Fitness Coach: ໃຊ້ AI ແນະນຳຕາຕະລາງການອອກກຳລັງກາຍ ແລະ ເມນູອາຫານໃຫ້ເໝາະສົມກັບຮ່າງກາຍແຕ່ລະຄົນ.
